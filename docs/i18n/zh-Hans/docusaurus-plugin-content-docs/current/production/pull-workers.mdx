# 拉取模式 Worker

拉取模式 Worker 主动向 Dex Server 建立任务 stream，不监听入站调用。Worker 无法开放入站端口、
位于 NAT 或防火墙后，或需要简化网络规则时，可选用拉取模式。如果 Worker 在内存中保存了
后续调用会用到的状态，也可以利用黏性路由。

## 启用拉取模式

设置 Worker 的 pull 选项和 Dex Server 地址。不要同时设置 bind address 或发布监听地址。
SDK 会从 Worker 提供拉取模式的 **WorkerTarget**。将它设为 Client 默认目标，或通过
**StartFlowOptions** 和 **FlowConfig.WorkerTarget** 为单个 Flow 选择它。SubFlow 可通过
**SubFlowOptions** 和相同的 **FlowConfig** override 选择它。Client 在单独的进程中运行时，
也可以直接使用拉取模式 **WorkerTarget**。

所有五种 SDK 都提供 pull 选项和目标。以下示例使用拉取模式 Worker 处理一个
Greeting Flow。Step 写入问候语，问候语 RPC 读取它。启动细节见
[Go](https://github.com/superdurable/dex/blob/main/sdk-go/README.md#running-a-worker)、
[Python](https://github.com/superdurable/dex/blob/main/sdk-python/README.md#pull-mode)、
[Java](https://github.com/superdurable/dex/blob/main/sdk-java/README.md#pull-mode)、
[TypeScript](https://github.com/superdurable/dex/blob/main/sdk-typescript/README.md#pull-mode) 和
[Rust](https://github.com/superdurable/dex/blob/main/sdk-rust/README.md#pull-mode)
SDK 的 README。

Dex Web v2 可以通过拉取模式 Worker 启动 Flow。在 **Start Flow** 中选择
**Pull Worker**，无需填写 Worker address。启动请求也可以发送
**workerTargetPull: true**。如果部署默认使用拉取模式 Worker，可设置
**web.startFlowWorkerTargetPull: true**，使未指定目标的请求使用 pull routing。
Dex Web 不会在启动前检查 pull Worker 是否已注册；Dex 在分配工作时确定其可用性。
Address 选项和配置规则见 [Dex Web](/production/dex-web)。

async def start_pull_greeting(
    cache: BlobCache, server_address: str
) -> tuple[GreetingFlow, AsyncWorker, AsyncClient, asyncio.Task[None]]:
    flow = GreetingFlow()
    registry = Registry((flow,), allow_async_handlers=True)
    worker = AsyncWorker(
        registry,
        cache,
        WorkerOptions(
            server_address=server_address,
            pull=PullWorkerOptions(
                max_concurrent_tasks=8,
                # Keep one slot for RPCs so Flows stay responsive.
                reserved_rpc_tasks=1,
            ),
        ),
    )
    worker_task = asyncio.create_task(worker.start())
    client = AsyncClient(
        registry,
        cache,
        ClientOptions(
            server_address=server_address,
            worker_target=worker.worker_target,
        ),
    )
    try:
        await worker.wait_pull_registered(timeout=30)
    except BaseException:
        await stop_pull_greeting(worker, client, worker_task)
        raise
    return flow, worker, client, worker_task


async def stop_pull_greeting(
    worker: AsyncWorker, client: AsyncClient, worker_task: asyncio.Task[None]
) -> None:
    await client.close()
    await worker.close()
    await worker_task

type PullGreetingDiagnostics struct {
	IsReady             bool
	ReservedRPCDeclines uint64
}

func StartPullGreeting(cache *blobcache.Cache, serverAddress string) (*GreetingFlow, *dex.Worker, *dex.Client, <-chan error, error) {
	flow := &GreetingFlow{}
	registry, err := dex.NewRegistry([]dex.Flow{flow})
	if err != nil {
		return nil, nil, nil, nil, err
	}
	worker, err := dex.NewWorker(registry, cache, dex.WorkerOptions{
		FlowServiceAddress: serverAddress,
		Pull: &dex.PullWorkerOptions{
			MaxConcurrentTasks: 8,
			// Keep one slot for RPCs so Flows stay responsive.
			ReservedRPCTasks: ptr.Any(1),
		},
	})
	if err != nil {
		return nil, nil, nil, nil, err
	}
	client, err := dex.NewClient(registry, cache, dex.ClientOptions{
		FlowServiceAddress: serverAddress,
		WorkerTarget:       worker.WorkerTarget(),
	})
	if err != nil {
		return nil, nil, nil, nil, errors.Join(err, worker.Stop(context.Background()))
	}
	workerResult := make(chan error, 1)
	go reportWorkerResult(worker, workerResult)
	startupContext, cancel := context.WithTimeout(context.Background(), 30*time.Second)
	defer cancel()
	if err := worker.WaitPullRegistered(startupContext); err != nil {
		return nil, nil, nil, nil, errors.Join(err, StopPullGreeting(context.Background(), worker, client, workerResult))
	}
	return flow, worker, client, workerResult, nil
}

func StopPullGreeting(ctx context.Context, worker *dex.Worker, client *dex.Client, workerResult <-chan error) error {
	clientCloseErr := client.Close()
	workerStopErr := worker.Stop(ctx)
	var workerRunErr error
	select {
	case workerRunErr = <-workerResult:
	case <-ctx.Done():
		workerRunErr = ctx.Err()
	}
	return errors.Join(clientCloseErr, workerStopErr, workerRunErr)
}

func PullGreetingReadiness(worker *dex.Worker) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if !worker.PullRegistrationState().IsReady {
			http.Error(w, "pull queues unavailable", http.StatusServiceUnavailable)
			return
		}
		w.WriteHeader(http.StatusOK)
	})
}

func GetPullGreetingDiagnostics(worker *dex.Worker) PullGreetingDiagnostics {
	return PullGreetingDiagnostics{
		IsReady:             worker.PullRegistrationState().IsReady,
		ReservedRPCDeclines: worker.PullReservedRPCDeclines(),
	}
}

func reportWorkerResult(worker *dex.Worker, workerResult chan<- error) {
	workerResult <- worker.Start()
}

public final class PullGreetingExample {
    private PullGreetingExample() {
    }

    public static RunningPullGreeting start(
            final BlobCache cache, final String serverAddress) throws InterruptedException, TimeoutException {
        final GreetingFlow flow = new GreetingFlow();
        final Registry registry = new Registry(List.<Flow<?>>of(flow));
        final Worker worker = new Worker(registry, cache, WorkerOptions.newBuilder()
                .serverAddress(serverAddress)
                .pull(PullWorkerOptions.newBuilder()
                        .maxConcurrentTasks(8)
                        // Keep one slot for RPCs so Flows stay responsive.
                        .reservedRpcTasks(1)
                        .build())
                .build());
        final Client client = new Client(registry, cache,
                new ClientOptions(serverAddress, worker.getWorkerTarget()));
        final CompletableFuture<Void> workerResult = new CompletableFuture<>();
        final Thread workerThread = new Thread(() -> {
            try {
                worker.start();
                workerResult.complete(null);
            } catch (final Throwable failure) {
                workerResult.completeExceptionally(failure);
            }
        }, "pull-greeting-worker");
        workerThread.start();
        final RunningPullGreeting running = new RunningPullGreeting(
                flow, worker, client, workerThread, workerResult);
        try {
            worker.waitPullRegistered(Duration.ofSeconds(30));
        } catch (final InterruptedException | TimeoutException | RuntimeException | Error failure) {
            try {
                running.close();
            } catch (final InterruptedException | RuntimeException | Error cleanupFailure) {
                failure.addSuppressed(cleanupFailure);
                if (cleanupFailure instanceof InterruptedException) {
                    Thread.currentThread().interrupt();
                }
            }
            throw failure;
        }
        return running;
    }

    public static boolean isPullGreetingReady(final Worker worker) {
        return worker.getPullRegistrationState().isReady();
    }

    public static PullGreetingDiagnostics getPullGreetingDiagnostics(final Worker worker) {
        return new PullGreetingDiagnostics(
                worker.getPullRegistrationState().isReady(), worker.getPullReservedRpcDeclines());
    }

    public record PullGreetingDiagnostics(boolean isReady, long reservedRpcDeclines) {
    }

    public record RunningPullGreeting(
            GreetingFlow flow, Worker worker, Client client, Thread workerThread,
            CompletableFuture<Void> workerResult) implements AutoCloseable {
        @Override
        public void close() throws InterruptedException {
            client.close();
            worker.close();
            workerThread.join();
            workerResult.join();
        }
    }
}

export async function startPullGreeting(
  cache: BlobCache,
  serverAddress: string,
): Promise<{ flow: GreetingFlow; worker: Worker; client: Client }> {
  const flow = new GreetingFlow();
  const registry = new Registry([flow]);
  const worker = new Worker(registry, cache, {
    serverAddress,
    pull: {
      maxConcurrentTasks: 8,
      // Keep one slot for RPCs so Flows stay responsive.
      reservedRpcTasks: 1,
    },
  });
  try {
    await worker.start();
    await worker.waitPullRegistered({ timeoutMs: 30_000 });
  } catch (failure) {
    try {
      await worker.close();
    } catch (cleanupFailure) {
      throw new AggregateError([failure, cleanupFailure], "pull Worker startup and cleanup failed");
    }
    throw failure;
  }
  const client = new Client(registry, cache, {
    serverAddress,
    workerTarget: worker.workerTarget,
  });
  return { flow, worker, client };
}

export async function stopPullGreeting(worker: Worker, client: Client): Promise<void> {
  await client.close();
  await worker.close();
}

pub type RunningPullGreeting = (Arc<Worker>, Client, JoinHandle<SdkResult<()>>);

pub fn start_pull_greeting(
    cache: Arc<BlobCache>,
    server_address: &str,
) -> Result<RunningPullGreeting, Box<dyn Error + Send + Sync>> {
    let registry = Registry::new().register(GreetingFlow::default())?;
    let worker = Arc::new(Worker::try_new(
        registry.clone(),
        Arc::clone(&cache),
        WorkerOptions::new().server_address(server_address).pull(
            PullWorkerOptions::new()
                .max_concurrent_tasks(8)
                // Keep one slot for RPCs so Flows stay responsive.
                .reserved_rpc_tasks(1),
        ),
    )?);
    let client = Client::try_new(
        registry,
        cache,
        ClientOptions::new()
            .server_address(server_address)
            .worker_target(worker.worker_target().clone()),
    )?;
    let startup_runtime = tokio::runtime::Builder::new_current_thread()
        .enable_all()
        .build()?;
    let running_worker = Arc::clone(&worker);
    let worker_thread = thread::spawn(move || running_worker.start());
    let startup_result: Result<(), Box<dyn Error + Send + Sync>> =
        startup_runtime.block_on(async {
            tokio::time::timeout(Duration::from_secs(30), worker.wait_pull_registered()).await??;
            Ok(())
        });
    if let Err(failure) = startup_result {
        match stop_pull_greeting(worker, client, worker_thread) {
            Ok(Ok(())) => {}
            Ok(Err(cleanup_failure)) => {
                eprintln!("pull Worker cleanup failed: {cleanup_failure}");
            }
            Err(panic) => std::panic::resume_unwind(panic),
        }
        return Err(failure);
    }
    Ok((worker, client, worker_thread))
}

pub fn stop_pull_greeting(
    worker: Arc<Worker>,
    client: Client,
    worker_thread: JoinHandle<SdkResult<()>>,
) -> thread::Result<SdkResult<()>> {
    worker.stop();
    let worker_result = worker_thread.join();
    drop(client);
    worker_result
}

## 就绪检查 {#readiness}

从 Go SDK 1.13.0 开始，**WaitPullRegistered** 会等待所有 Flow type 队列和
app Worker ID 队列收到注册确认后再允许启动流程继续。Java 提供
**waitPullRegistered(Duration)** 和 **getPullRegistrationState()**。
Python 的 Worker 和 AsyncWorker 均提供 **wait_pull_registered(timeout)** 和
**pull_registration_state()**；AsyncWorker 的等待方法需要 await。
Java 的 **stopOnPermanentStreamRejection** 和 Python 的
**stop_on_permanent_stream_rejection** 提供与 Go 相同的可选停止行为。
在独立 goroutine 中调用 **Start**，然后设置启动截止时间并等待注册完成。
滚动部署时，先等待新 Worker 就绪，再停止旧 Worker。注册成功不代表处理器
仍有空闲容量。

TypeScript 提供 **waitPullRegistered**、**pullRegistrationState** 和
**stopOnPermanentStreamRejection**。Rust 提供 **wait_pull_registered**、
**pull_registration_state** 和 **stop_on_permanent_stream_rejection**，就绪语义相同。
TypeScript 等待支持 AbortSignal 或毫秒超时；Rust 可通过丢弃 future 取消等待，
或使用 Tokio 超时。启用停止选项后，TypeScript 的 **run** 和 Rust 的 **start**
会在排空后返回永久拒绝错误。

**WaitPullRegistered** 支持并发调用，也可以在 **Start** 之前调用。
如果就绪前发生永久拒绝，且该队列没有其他已注册的 stream，它会返回包含
队列名称和底层 gRPC 错误的 **PullRegistrationError**。只要同一队列仍有其他
已注册的 stream，多余 stream 的拒绝就只会被记录并重试。**Start** 的启动错误也会传递给等待方。
取消等待会返回 context 错误；就绪前停止 Worker 会返回错误。
所有队列都注册成功过一次后，后续等待始终成功。

这些可运行示例使用 30 秒启动期限等待注册，启动失败时会停止 Worker。
Go SDK 从 1.13.0 开始提供就绪 API；Java、Python、TypeScript 和 Rust SDK 从 1.14.0 开始提供。
将 Go HTTP handler 挂载到就绪探针端点。其他语言可在探针端点调用布尔值 helper：
返回 true 时响应 200，返回 false 时响应 503。

**Queues** 提供每个队列的 **HasRegisteredStream** 和
**LastPermanentError**。首次就绪后，重连、所有权迁移、临时断连和退避
都保持 **IsReady** 为 true。只有某个队列既没有已注册的 stream，
又存在永久错误时，它才变为 false。重新注册成功会清除该队列的永久错误；
其他队列均正常时，就绪状态恢复。单独调用 **Stop** 不会清除就绪状态；
关闭时应另行将 Worker 从服务中移除。

**StopOnPermanentStreamRejection** 默认为 false，保留自动重试行为。
设为 true 后，首次导致其队列没有任何已注册 stream 的永久拒绝会让
**Start** 返回 **PullRegistrationError**，即使 Worker 已经就绪。
同一队列仍有其他已注册 stream 时，拒绝不会停止 Worker。**Start** 排空其他队列时，这些队列仍可能持有 stream。
排空时间由 **StopDrainTimeout** 限制，超时后请求取消并等待处理器返回。
处理器必须响应取消。退出前始终调用 **Stop**；**Start** 返回后仍可安全调用。

## 路由和可用性

每个拉取模式 Worker 都轮询自己的 app Worker ID 队列，以及注册的每个 Flow 类型队列。
Dex 首先尝试此前服务该 Flow 的 app Worker ID。该 ID 没有任何已连接的 stream 时，例如
Worker 重启或部署后，Dex 会立即改用 Flow 类型队列。否则，Dex 在黏性等待结束后改用
Flow 类型队列，让其他 Worker 接手。黏性路由是尽力而为；持久状态应保存在 Dex 中，不应依赖某个
Worker 的内存。同一个 Dex Server 内的 Flow 类型名称必须唯一。app Worker ID 必须
唯一标识一个 Worker 进程，并在该进程重启后变化。未显式设置时，SDK 会生成 ID。

Dex 在 matching dispatch 等待时间内寻找可用 Worker。如果没有 Worker，Step 会收到
可重试的 unavailable 错误，并消耗一次 Step 重试。RPC 调用方则直接收到
**Unavailable** 错误。普通 dispatch
默认等待 10 秒，其中有已连接 stream 的黏性队列最多等待 5 秒。需要保留执行时间的调用使用更短的等待。
等待设置见[服务器运维](/production/server-operations#pull-worker-routing)。

如果拉取模式 Worker 注册了该 Flow 类型，却没有请求的 Step 类型或 RPC 名称，
它会在运行 handler 前拒绝任务。Dex 会立即改用 Flow 类型队列，并在本次分配中
排除该 Worker，即使 Flow 原本黏附于它。重新分配不会消耗 Step attempt。
如果在 dispatch 等待时间内没有可处理任务的 Worker，Step 会按其失败和重试策略
收到注明 Step 或 RPC 名称的错误；RPC 调用方会在最多等待常规 dispatch 等待时间
（10 秒）后直接收到该错误。此重新分配需要支持它的 Dex Server 版本。面对旧版
Server，Worker 与之前一样返回未注册错误。推送模式 Worker 仍返回原有的未注册名称错误。

任务至少投递一次。如果 Worker 在 Dex 收到任何输出前断开连接，同一个调用可能再次分配。
外部副作用应具备幂等性，例如使用 Flow ID 和 Step execution ID 作为幂等键。

使用拉取模式 Worker 时，**ASYNC** durability 的本地阶段只有一次 attempt；后续 attempt
会收到该阶段结束后记录的上一次 heartbeat。

## 容量和关闭

并发任务上限限制同时运行的调用数。每队列的空闲 stream 数量使 stream 随时可用。
默认值分别为 CPU 核心数和每队列一个空闲 stream。每条 stream 一次只处理
一个调用。达到容量上限时，Worker 仍保留空闲 stream，并拒绝额外分配，让 Dex 尝试
其他 Worker。

| SDK | 并发任务数 | 每队列空闲 stream 数 | 停止时的排空期限 | 关闭方法 |
| --- | --- | --- | --- | --- |
| Go | **MaxConcurrentTasks** | **IdleStreamsPerQueue** | **StopDrainTimeout** | **Stop** |
| Python | **max_concurrent_tasks** | **idle_streams_per_queue** | **stop_drain_timeout** | **stop** |
| Java | **maxConcurrentTasks** | **idleStreamsPerQueue** | **stopDrainTimeout** | **stop** |
| TypeScript | **maxConcurrentTasks** | **idleStreamsPerQueue** | **stopDrainTimeoutMs** | **close** |
| Rust | **max_concurrent_tasks** | **idle_streams_per_queue** | **stop_drain_timeout** | **stop** |

表中 Java 和 Rust 的选项名称是 builder method。下方公式使用 TypeScript 的两个容量参数名称；
同一上限适用于所有 SDK。

任务完成后，Worker 会正常关闭多余的空闲 stream。每个队列保留至少
**idleStreamsPerQueue** 条已注册的空闲 stream，清理期间就绪状态保持为 true。
对于注册了 **F** 个 Flow 类型的 Worker，负载下降后的稳态上限为
**maxConcurrentTasks + (F + 1) × idleStreamsPerQueue** 条 stream。
额外的队列是该 Worker 的 app Worker ID 队列。突发负载期间的瞬时峰值仍受 matching
容量上限约束。应根据 **matching.maxConcurrentTasksCap** 配置 Worker；
默认每个 matching owner 上每个 app Worker ID 最多 256 条 stream。
**matching.maxStreams** 默认限制每个 Matching 实例最多注册 100,000 条 stream。
**matching.maxQueueLength**、**matching.maxFlowTypes** 和
**matching.maxFlowTypeLength** 也限制注册内容，默认值均为 256。

部署期间应正常停止 Worker。关闭方法会停止接收新调用，并在配置的排空期限内等待正在运行的
handler，默认期限为 30 秒。超过期限后，它请求取消，并等待 handler
返回。长时间运行的 handler 应响应取消。Server 要求重新连接时，Worker 也会先完成
正在运行的调用。

### 为 RPC 预留容量

SDK 1.15.0 预留 RPC 容量，使 Step 长时间运行时，同步 RPC 仍能及时响应。
Go 使用 **ReservedRPCTasks**，Java 和 TypeScript 使用 **reservedRpcTasks**，
Python 和 Rust 使用 **reserved_rpc_tasks**。未设置时，如果解析后的任务上限至少为二，
默认预留一个槽位；上限为一时则预留零个。使用 CPU 数量默认值时，Step 比以前少一个槽位。
显式设置为零可以关闭预留。上限为一且未显式设置预留值时，Worker 启动会记录一次警告：
RPC 可能等待长时间运行的 Step，并建议将上限设为至少二，或显式设置预留值。
Step 占用其余容量时，预留槽位可让 Flow 保持响应。
预留值必须非负，并且小于解析 CPU 数量默认值后的并发任务上限。
无效值会导致 Worker 构造失败。

RPC 任务包括 API 直接调用和事务型 **InvokeWorkerRPC** 任务。
RPC 和 Step 的处理函数共同计入任务上限。当忙碌处理函数数量达到任务上限减去预留值时，
Worker 会以 **NO_CAPACITY** 拒绝所有 Step 任务，包括 WaitFor、Execute 和本地（ASYNC 第一阶段）尝试。RPC 任务可以使用全部容量。
例如，上限为八、预留值为二时，只有忙碌处理函数少于六个，才能启动新的 Step 任务。

Dex 会尝试其他 Worker，不消耗 Step 尝试次数。如果所有 Worker 都持续达到 Step 容量上限，
Step 最多等待到分发等待时间结束，然后收到 **NO_WORKER_AVAILABLE**、消耗一次尝试并遵循其重试策略，
与所有 Worker 都已满载时相同。本地尝试等待本地分发等待时间，然后按照其策略回退。
每个队列仍保留可用的空闲流。
预留容量导致的拒绝不会关闭流，也不会改变注册就绪状态。
每次此类拒绝都会生成包含 Flow 类型的调试日志，并增加 Worker 的累计预留拒绝计数：
Go 为 **PullReservedRPCDeclines()**，Java 为 **getPullReservedRpcDeclines()**，
TypeScript 为 **pullReservedRpcDeclines**，Python 为 **pull_reserved_rpc_declines**，
Rust 为 **pull_reserved_rpc_declines()**。满载拒绝和未知名称不会增加此计数。
计数从不重置，关闭后仍可读取，监听模式 Worker 返回零。日志配置请参阅各 SDK 的 README。

上面的启动示例将任务上限设为八，并显式为 RPC 预留一个槽位，与默认值一致。
下面的诊断函数返回注册就绪状态和累计预留拒绝计数，供监控使用。

## 缩容到零

Worker 可能缩容到零时，配置 [Worker 唤醒 hook](/production/server-operations#worker-wake-hook)。
拉取模式 Worker 不可用时，Dex 会在黏性等待结束后为 Flow 类型队列发送尽力而为的唤醒通知，
并继续同一次 dispatch 尝试。成功分配后，Dex 会发送 active 通知。应按 Worker 启动时间
设置 dispatch 等待和 Step 重试；唤醒通知不保证 Worker 及时启动。

## Server 和网络配置

**matching** 角色管理拉取模式 Worker 队列。至少保持一个 Matching 实例运行。Worker
通过公开的 FlowService 端口连接 API 实例；API 会将 stream 转发给队列 owner。负载均衡器
应支持双向 HTTP/2 streaming，idle timeout 要长于 **matching.pingInterval**，默认
为 20 秒。忙碌的 stream 不会收到空闲 Ping，因此 handler 应足够频繁地发送任务心跳，
以保持连接活跃。

单个 Server 进程使用本地 membership ring。多个 Server 实例需要在每个进程配置
**membership** 和私有的 **internal.listen**。所有实例应使用相同的 backend namespace
和 membership seeds。私有 listener 必须配置 **internal.tokenFile**，只允许 Dex 副本访问。
[服务器运维](/production/server-operations#pull-worker-routing)列出了 matching 限制、
等待设置和多节点配置。

Go、Python、Java、TypeScript 和 Rust SDK，以及 **dexcli** 和 Dex Web，均可发送所需的 bearer credential。
Worker 和 Client 各有 credential 选项。
参阅[身份认证设置](/production/server-operations#authentication)。
