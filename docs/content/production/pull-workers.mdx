# Pull Workers

A pull Worker opens outbound task streams to Dex Server instead of listening for
incoming calls. Choose pull mode when Workers cannot expose an inbound port, run
behind NAT or firewalls, or need simpler network rules. Pull mode also offers
sticky routing when a Worker keeps useful state in memory between calls.

## Enable pull mode

Set the Worker's pull option and its Dex Server address. Do not set a bind
address or advertise a listening address for the same Worker. The SDK exposes a
pull **WorkerTarget** from the Worker. Set that target as the Client's default,
or select it for one Flow with **StartFlowOptions** and
**FlowConfig.WorkerTarget**. A SubFlow can select it with **SubFlowOptions** and
the same **FlowConfig** override. Use a pull **WorkerTarget** without a local
Worker when the Client runs in a separate process.

All five SDKs provide pull options and targets. This example serves a Greeting
Flow through a pull Worker. Its Step stores a greeting, and the greeting RPC
reads it. See the [Go](https://github.com/superdurable/dex/blob/main/sdk-go/README.md#running-a-worker),
[Python](https://github.com/superdurable/dex/blob/main/sdk-python/README.md#pull-mode),
[Java](https://github.com/superdurable/dex/blob/main/sdk-java/README.md#pull-mode),
[TypeScript](https://github.com/superdurable/dex/blob/main/sdk-typescript/README.md#pull-mode),
and [Rust](https://github.com/superdurable/dex/blob/main/sdk-rust/README.md#pull-mode)
READMEs for startup details.

Dex Web v2 can start a Flow through a pull Worker. In **Start Flow**, select
**Pull Worker** instead of entering a Worker address. The start request can also
send **workerTargetPull: true**. For deployments that use pull Workers by default,
set **web.startFlowWorkerTargetPull: true** so requests without a target use pull
routing. Dex Web does not check whether a pull Worker is registered before the
start; availability is determined when Dex dispatches work. See
[Dex Web](/production/dex-web#start-flow) for the address option and config rules.

async def start_pull_greeting(
    cache: BlobCache, server_address: str
) -> tuple[GreetingFlow, AsyncWorker, AsyncClient, asyncio.Task[None]]:
    flow = GreetingFlow()
    registry = Registry((flow,), allow_async_handlers=True)
    worker = AsyncWorker(
        registry,
        cache,
        WorkerOptions(
            server_address=server_address,
            pull=PullWorkerOptions(
                max_concurrent_tasks=8,
                # Keep one slot for RPCs so Flows stay responsive.
                reserved_rpc_tasks=1,
            ),
        ),
    )
    worker_task = asyncio.create_task(worker.start())
    client = AsyncClient(
        registry,
        cache,
        ClientOptions(
            server_address=server_address,
            worker_target=worker.worker_target,
        ),
    )
    try:
        await worker.wait_pull_registered(timeout=30)
    except BaseException:
        await stop_pull_greeting(worker, client, worker_task)
        raise
    return flow, worker, client, worker_task


async def stop_pull_greeting(
    worker: AsyncWorker, client: AsyncClient, worker_task: asyncio.Task[None]
) -> None:
    await client.close()
    await worker.close()
    await worker_task

func StartPullGreeting(cache *blobcache.Cache, serverAddress string) (*GreetingFlow, *dex.Worker, *dex.Client, <-chan error, error) {
	flow := &GreetingFlow{}
	registry, err := dex.NewRegistry([]dex.Flow{flow})
	if err != nil {
		return nil, nil, nil, nil, err
	}
	worker, err := dex.NewWorker(registry, cache, dex.WorkerOptions{
		FlowServiceAddress: serverAddress,
		Pull: &dex.PullWorkerOptions{
			MaxConcurrentTasks: 8,
			// Keep one slot for RPCs so Flows stay responsive.
			ReservedRPCTasks: ptr.Any(1),
		},
	})
	if err != nil {
		return nil, nil, nil, nil, err
	}
	client, err := dex.NewClient(registry, cache, dex.ClientOptions{
		FlowServiceAddress: serverAddress,
		WorkerTarget:       worker.WorkerTarget(),
	})
	if err != nil {
		return nil, nil, nil, nil, errors.Join(err, worker.Stop(context.Background()))
	}
	workerResult := make(chan error, 1)
	go reportWorkerResult(worker, workerResult)
	startupContext, cancel := context.WithTimeout(context.Background(), 30*time.Second)
	defer cancel()
	if err := worker.WaitPullRegistered(startupContext); err != nil {
		return nil, nil, nil, nil, errors.Join(err, StopPullGreeting(context.Background(), worker, client, workerResult))
	}
	return flow, worker, client, workerResult, nil
}

func StopPullGreeting(ctx context.Context, worker *dex.Worker, client *dex.Client, workerResult <-chan error) error {
	clientCloseErr := client.Close()
	workerStopErr := worker.Stop(ctx)
	var workerRunErr error
	select {
	case workerRunErr = <-workerResult:
	case <-ctx.Done():
		workerRunErr = ctx.Err()
	}
	return errors.Join(clientCloseErr, workerStopErr, workerRunErr)
}

func PullGreetingReadiness(worker *dex.Worker) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if !worker.PullRegistrationState().IsReady {
			http.Error(w, "pull queues unavailable", http.StatusServiceUnavailable)
			return
		}
		w.WriteHeader(http.StatusOK)
	})
}

func GetPullGreetingDiagnostics(worker *dex.Worker) PullGreetingDiagnostics {
	return PullGreetingDiagnostics{
		IsReady:             worker.PullRegistrationState().IsReady,
		ReservedRPCDeclines: worker.PullReservedRPCDeclines(),
	}
}

func reportWorkerResult(worker *dex.Worker, workerResult chan<- error) {
	workerResult <- worker.Start()
}

    public static RunningPullGreeting start(
            final BlobCache cache, final String serverAddress) throws InterruptedException, TimeoutException {
        final GreetingFlow flow = new GreetingFlow();
        final Registry registry = new Registry(List.<Flow<?>>of(flow));
        final Worker worker = new Worker(registry, cache, WorkerOptions.newBuilder()
                .serverAddress(serverAddress)
                .pull(PullWorkerOptions.newBuilder()
                        .maxConcurrentTasks(8)
                        // Keep one slot for RPCs so Flows stay responsive.
                        .reservedRpcTasks(1)
                        .build())
                .build());
        final Client client = new Client(registry, cache,
                new ClientOptions(serverAddress, worker.getWorkerTarget()));
        final CompletableFuture<Void> workerResult = new CompletableFuture<>();
        final Thread workerThread = new Thread(() -> {
            try {
                worker.start();
                workerResult.complete(null);
            } catch (final Throwable failure) {
                workerResult.completeExceptionally(failure);
            }
        }, "pull-greeting-worker");
        workerThread.start();
        final RunningPullGreeting running = new RunningPullGreeting(
                flow, worker, client, workerThread, workerResult);
        try {
            worker.waitPullRegistered(Duration.ofSeconds(30));
        } catch (final InterruptedException | TimeoutException | RuntimeException | Error failure) {
            try {
                running.close();
            } catch (final InterruptedException | RuntimeException | Error cleanupFailure) {
                failure.addSuppressed(cleanupFailure);
                if (cleanupFailure instanceof InterruptedException) {
                    Thread.currentThread().interrupt();
                }
            }
            throw failure;
        }
        return running;
    }

    public static boolean isPullGreetingReady(final Worker worker) {
        return worker.getPullRegistrationState().isReady();
    }

    public static PullGreetingDiagnostics getPullGreetingDiagnostics(final Worker worker) {
        return new PullGreetingDiagnostics(
                worker.getPullRegistrationState().isReady(), worker.getPullReservedRpcDeclines());
    }

    public record PullGreetingDiagnostics(boolean isReady, long reservedRpcDeclines) {
    }

    public record RunningPullGreeting(
            GreetingFlow flow, Worker worker, Client client, Thread workerThread,
            CompletableFuture<Void> workerResult) implements AutoCloseable {
        @Override
        public void close() throws InterruptedException {
            client.close();
            worker.close();
            workerThread.join();
            workerResult.join();
        }
    }
}

export async function startPullGreeting(
  cache: BlobCache,
  serverAddress: string,
): Promise<{ flow: GreetingFlow; worker: Worker; client: Client }> {
  const flow = new GreetingFlow();
  const registry = new Registry([flow]);
  const worker = new Worker(registry, cache, {
    serverAddress,
    pull: {
      maxConcurrentTasks: 8,
      // Keep one slot for RPCs so Flows stay responsive.
      reservedRpcTasks: 1,
    },
  });
  try {
    await worker.start();
    await worker.waitPullRegistered({ timeoutMs: 30_000 });
  } catch (failure) {
    try {
      await worker.close();
    } catch (cleanupFailure) {
      throw new AggregateError([failure, cleanupFailure], "pull Worker startup and cleanup failed");
    }
    throw failure;
  }
  const client = new Client(registry, cache, {
    serverAddress,
    workerTarget: worker.workerTarget,
  });
  return { flow, worker, client };
}

export async function stopPullGreeting(worker: Worker, client: Client): Promise<void> {
  await client.close();
  await worker.close();
}

pub type RunningPullGreeting = (Arc<Worker>, Client, JoinHandle<SdkResult<()>>);

pub fn start_pull_greeting(
    cache: Arc<BlobCache>,
    server_address: &str,
) -> Result<RunningPullGreeting, Box<dyn Error + Send + Sync>> {
    let registry = Registry::new().register(GreetingFlow::default())?;
    let worker = Arc::new(Worker::try_new(
        registry.clone(),
        Arc::clone(&cache),
        WorkerOptions::new().server_address(server_address).pull(
            PullWorkerOptions::new()
                .max_concurrent_tasks(8)
                // Keep one slot for RPCs so Flows stay responsive.
                .reserved_rpc_tasks(1),
        ),
    )?);
    let client = Client::try_new(
        registry,
        cache,
        ClientOptions::new()
            .server_address(server_address)
            .worker_target(worker.worker_target().clone()),
    )?;
    let startup_runtime = tokio::runtime::Builder::new_current_thread()
        .enable_all()
        .build()?;
    let running_worker = Arc::clone(&worker);
    let worker_thread = thread::spawn(move || running_worker.start());
    let startup_result: Result<(), Box<dyn Error + Send + Sync>> =
        startup_runtime.block_on(async {
            tokio::time::timeout(Duration::from_secs(30), worker.wait_pull_registered()).await??;
            Ok(())
        });
    if let Err(failure) = startup_result {
        match stop_pull_greeting(worker, client, worker_thread) {
            Ok(Ok(())) => {}
            Ok(Err(cleanup_failure)) => {
                eprintln!("pull Worker cleanup failed: {cleanup_failure}");
            }
            Err(panic) => std::panic::resume_unwind(panic),
        }
        return Err(failure);
    }
    Ok((worker, client, worker_thread))
}

pub fn stop_pull_greeting(
    worker: Arc<Worker>,
    client: Client,
    worker_thread: JoinHandle<SdkResult<()>>,
) -> thread::Result<SdkResult<()>> {
    worker.stop();
    let worker_result = worker_thread.join();
    drop(client);
    worker_result
}

## Readiness

Starting with Go SDK 1.13.0, **WaitPullRegistered** gates startup until every
Flow type queue and the app Worker ID queue has received a registration
acknowledgement. Java provides **waitPullRegistered(Duration)** and
**getPullRegistrationState()**. Python provides **wait_pull_registered(timeout)**
and **pull_registration_state()** on both Worker and AsyncWorker; await the
AsyncWorker wait. Java's **stopOnPermanentStreamRejection** and Python's
**stop_on_permanent_stream_rejection** provide the same opt-in shutdown behavior
as Go. Start the Go Worker in a goroutine,
then wait with a startup deadline before activating it or stopping the old
Worker during a rolling deployment. Registration does not guarantee spare
handler capacity.

TypeScript exposes **waitPullRegistered**, **pullRegistrationState**, and
**stopOnPermanentStreamRejection**. Rust exposes **wait_pull_registered**,
**pull_registration_state**, and **stop_on_permanent_stream_rejection** with the
same readiness semantics. TypeScript waits accept an AbortSignal or timeout in
milliseconds; Rust waits can be cancelled by dropping the future or bounded with
a Tokio timeout. Opt-in fatal rejections are returned by TypeScript **run** and
Rust **start** after draining.

**WaitPullRegistered** is safe to call concurrently, including before
**Start**. It returns a **PullRegistrationError** with the queue name and
underlying gRPC error on a permanent rejection before readiness when the queue
has no other registered stream. A rejected surplus stream is recorded and retried
while another registered stream holds that queue. Startup errors
from **Start** also reach the waiter. Cancellation returns the context error;
stopping before readiness returns an error. Once all queues have registered,
this wait keeps returning successfully.

The runnable examples wait for registration with a 30-second startup deadline and
stop the Worker if startup fails. Go provides readiness in SDK 1.13.0; Java,
Python, TypeScript, and Rust provide it in SDK 1.14.0. Register the Go HTTP handler
at your readiness probe endpoint. In the other languages, call the boolean helper
from your probe endpoint and return 200 when true or 503 when false.

**Queues** reports each queue's **HasRegisteredStream** and
**LastPermanentError**. After initial registration, reconnects, ownership moves,
transient disconnects, and backoff keep **IsReady** true. It becomes false only
when a queue has no registered stream and a permanent error. Successful
registration clears that queue's error and restores readiness when no other
queue is failing. Stop alone does not clear readiness; remove the Worker from
service during shutdown separately.

**StopOnPermanentStreamRejection** defaults to false, preserving retries.
Set it to true to make **Start** return a **PullRegistrationError** for the first
permanent rejection that leaves its queue without a registered stream, even
after readiness. Rejections while another stream holds the same queue do not stop
the Worker. Other queues may still hold streams
while **Start** drains them. Draining uses **StopDrainTimeout**, then requests
cancellation and waits for handlers to return. Handlers must respond to
cancellation. Always call **Stop** before exiting; it remains safe after
**Start** returns.

## Routing and availability

Each pull Worker polls its own app Worker ID queue and every Flow type it
registers. Dex first tries the app Worker ID that served the Flow previously.
When no stream for that ID remains connected, such as after a Worker restart or
deployment, Dex immediately tries the Flow type queue. Otherwise, it tries the
Flow type queue after the sticky wait so another Worker can take the call. Sticky
routing is best effort; keep durable state in Dex rather than
depending on one Worker's memory. Flow type names must be unique within a Dex
Server. An app Worker ID must identify one Worker process and change when that
process restarts. The SDK generates one unless you set it explicitly.

Dex waits for an available Worker within the matching dispatch budget. If none
is available, a Step receives a retryable unavailable error that consumes a
Step retry. An RPC caller receives an **Unavailable** error directly. The default regular dispatch wait is 10 seconds,
including up to 5 seconds for a sticky queue with connected streams. Shorter waits apply to calls
that need to preserve time for execution. See [Server operation](/production/server-operations#pull-worker-routing)
for the wait settings.

When a pull Worker has the Flow type but lacks the requested Step type or RPC
name, it declines the task before running a handler. Dex immediately tries the
Flow type queue and excludes that Worker from this dispatch, even if the Flow
was sticky to it. This reassignment does not consume a Step attempt. If no
capable Worker accepts within the dispatch wait, the Step follows its failure
and retry policy with an error that names the Step or RPC. An RPC caller gets
the named error directly after waiting up to the regular dispatch wait of 10
seconds. This reassignment requires a Dex Server release that supports it.
Against older Servers, the Worker returns the not-registered error as before.
Push Workers still return their ordinary missing-name error.

Delivery is at least once. A call can be assigned again when its Worker
disconnects before Dex receives any output. Make external side effects
idempotent, for example by using the Flow ID and Step execution ID as an
idempotency key.

With a pull Worker, the local phase of **ASYNC** durability lasts one attempt;
later attempts receive the last heartbeat recorded after that phase.

## Capacity and shutdown

The concurrent task limit caps active calls. The idle stream count keeps
streams ready on each queue. Defaults are the CPU count and one idle stream per
queue. Each stream handles one call at a time. At capacity, a Worker keeps its
idle streams and declines an extra assignment so Dex can try another Worker.

| SDK | Concurrent tasks | Idle streams per queue | Stop drain timeout | Shutdown |
| --- | --- | --- | --- | --- |
| Go | **MaxConcurrentTasks** | **IdleStreamsPerQueue** | **StopDrainTimeout** | **Stop** |
| Python | **max_concurrent_tasks** | **idle_streams_per_queue** | **stop_drain_timeout** | **stop** |
| Java | **maxConcurrentTasks** | **idleStreamsPerQueue** | **stopDrainTimeout** | **stop** |
| TypeScript | **maxConcurrentTasks** | **idleStreamsPerQueue** | **stopDrainTimeoutMs** | **close** |
| Rust | **max_concurrent_tasks** | **idle_streams_per_queue** | **stop_drain_timeout** | **stop** |

The Java and Rust option names are builder methods. The formula below uses the TypeScript
spellings for the two capacity values; the same bound applies to every SDK.

A Worker gracefully closes surplus idle streams after tasks finish. Each queue
keeps at least **idleStreamsPerQueue** registered idle streams, and readiness stays
true during this cleanup. With **F** registered Flow types, the steady-state bound
after load drops is **maxConcurrentTasks + (F + 1) × idleStreamsPerQueue** streams.
The extra queue is the Worker's app Worker ID queue. The transient peak during a
burst remains bounded by the matching caps. Size the Worker for
**matching.maxConcurrentTasksCap**, which defaults to 256 streams per app Worker
ID on each matching owner. **matching.maxStreams** defaults to 100,000
registered streams per Matching instance. **matching.maxQueueLength**,
**matching.maxFlowTypes**, and **matching.maxFlowTypeLength** also limit
registration. Their defaults are 256 each.

Stop the Worker gracefully during deployment. The shutdown method stops taking
new calls and waits for active handlers for the configured drain timeout, 30
seconds by default. After the deadline, it requests cancellation and waits for handlers
to return. Long-running handlers should respond to cancellation. A Worker also
finishes an active call before a server-directed reconnect.

### Reserved RPC capacity

SDK 1.15.0 reserves capacity so synchronous RPC calls can stay responsive while
Steps run for a long time. Set **ReservedRPCTasks** in Go, **reservedRpcTasks** in
Java and TypeScript, or **reserved_rpc_tasks** in Python and Rust. When unset, the reserve
is one if the resolved task limit is at least two, otherwise zero. With the
CPU-count default, Steps get one fewer slot than before. Set the reserve to zero
to opt out. With a task limit of one and no explicit reserve, Worker start logs
one warning that RPCs may wait behind long-running Steps and recommends a limit
of at least two or an explicit reserve. The reserved slot keeps Flows responsive
while Steps occupy the remaining capacity.

The reserve must be nonnegative and less than the concurrent task limit after
its CPU-count default is resolved. Invalid values fail Worker construction.

RPC tasks include both API-direct and transactional **InvokeWorkerRPC** tasks.
RPC and Step handlers count together against the task limit. Every Step task,
WaitFor and Execute alike, including local (ASYNC first-phase) attempts, is
declined with **NO_CAPACITY** when the busy count reaches the task limit minus
the reserve. RPC tasks can use the full limit. For example, a limit of eight
and a reserve of two lets Steps start only while fewer than six handlers are busy.

Dex tries other Workers without consuming a Step attempt. If all Workers remain
at their Step limit, a Step can wait until the dispatch wait expires, then receive
**NO_WORKER_AVAILABLE**, consume an attempt, and follow its retry policy, as when
all Workers are full. A local attempt waits the local dispatch wait and then falls
back according to its policy.
Idle streams stay available on every queue. Reserve declines do not close streams
or change registration readiness. Each SDK emits a debug log with the Flow type
for each reserve decline. Each Worker also exposes a cumulative reserve-decline
counter: **PullReservedRPCDeclines()** in Go, **getPullReservedRpcDeclines()** in Java,
**pullReservedRpcDeclines** in TypeScript, **pull_reserved_rpc_declines** in Python,
and **pull_reserved_rpc_declines()** in Rust. Full-capacity rejections and unknown
names do not increment it. The count never resets, remains available after shutdown,
and is zero for listening Workers. See each SDK README for logger configuration.

The startup examples set the task limit to eight and explicitly reserve one slot
for RPCs, matching the default. These diagnostics helpers expose registration
readiness and the cumulative reserve-decline counter for monitoring. A rising
counter indicates Step capacity pressure; it does not make the Worker unready.

## Scale to zero

Configure the [Worker wake hook](/production/server-operations#worker-wake-hook)
when Workers may scale to zero. If a pull Worker is unavailable, Dex sends a
best-effort wake notification for the Flow type queue after the sticky wait and
continues the same dispatch attempt. After successful dispatch, Dex sends an
active notification. Size the dispatch wait and Step retries for Worker startup
time; the wake notification does not guarantee that a Worker starts in time.

## Server and network setup

The **matching** role owns pull Worker queues. Keep at least one Matching
instance running. Workers connect to an API instance on the public FlowService
port; the API forwards their streams to the queue owner. Preserve bidirectional
HTTP/2 streaming and set the load balancer idle timeout above
**matching.pingInterval**, which defaults to 20 seconds. Busy streams do not
receive idle Pings, so handlers should send task heartbeats often enough to
keep their connections active.

For one Server process, Dex uses a local membership ring. For multiple Server
instances, configure **membership** and a private **internal.listen** on each
process. Use the same backend namespace and membership seeds across instances.
**internal.tokenFile** is required for the private listener. Allow only Dex replicas
to reach it. The [Server operation](/production/server-operations#pull-worker-routing)
page shows the matching limits, wait settings, and multi-node configuration.
